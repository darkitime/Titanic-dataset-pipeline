# Titanic Dataset — End-to-End ML & DL Pipeline

Модульный, воспроизводимый пайплайн Classic ML и DNN для решения задачи бинарной классификации на датасете **Titanic** (Kaggle).

Структура проекта: предобработка и конструирования признаков, кросс-валидация классических моделей (`scikit-learn`, `CatBoost`, `XGBoost`, `LightGBM`), табличной полносвязной нейросети (`PyTorch`), блендинга и инференса.

---

## Results and leaderboard

Все модели обучались по схеме **5-Fold Stratified Cross-Validation**. Оценка качества проводилась на валидационных фолдах (Out-Of-Fold Accuracy), на отложенной тестовой выборке с известной разметкой (Local Test Accuracy) и на платформе Kaggle (Public Leaderboard Score).

### Ключевые выводы
* **Обобщающая способность:**  `LogisticRegression` и `TabularMLP` показали наилучшие результаты на PS (**0.78468** и **0.77751** соответственно). На валидации лидируют бустинги (~0.844). Возможная причина различия - разная природа распределения тестовой и тренировочной выборки. Градиентные бустинги уловили помимо линейных зависимостей (что чаще умирали мужчины) и нелинейные: Pclass, Fare etc... Выборка сама по себе небольшая: около 1500. Поэтому обобщающая способность низкая.
* **Корреляция валидации:** Точность на локальной тестовой выборке показала высокую корреляцию с результатами публичного лидерборда Kaggle для всех 8 алгоритмов. Хоть изначально платформа Kaggle предлагает в качестве тестовой выборки гендерно-детерминированное правило, на публичном скоре, можно понять, используется реальная разметка таргетов. Малые различия имеют место, возможно, из-за ошибки при создании корректного датасета для теста.
* **Ансамблирование:** Усреднение вероятностей предсказаний моделей (soft-voting blending) доступно через модуль `inference.py`. Скор на PS уступает логистической регресии и нейросети.

### Замечания по улучшению скоров

* **Hyperparameters** В нотбуке была реализована прогонка по гиперпараметрам. В случае ClassicML скор смотрелся на кросс валидации. В случае DNN скор смотрелся на hold-out валидационной выборке, причем seed не фиксировался. Хоть для прогонки на тесте и была выбрана модель с самым высоким скором на валидации, утверждать, что она 'лучше' остальных - нельзя. Для улучшения результатов стоит прогнать еще раз гиперпараметры на кросс-валидации при фиксированном сиде.(Или по крайней мере просто зафиксировать сид).
* **ClassicMl** Градиентные бустинги имеют, по сравнению с бейзлайном, большое число гиперпараметров. Для улучшения скора следует прогнать большее число гиперпараметров, нежели было сделано в нотбуке.
* **Feature Engineering** В нотбуке было изучено влияния только одной сгенерированной фичи на метрику. Стоит попробовать придумать еще несколько.

## Архитектура проекта

```text
├── configs/                     # Конфигурации экспериментов
│   ├── config_CL.py             # Настройки классических моделей
│   └── config_DNN.py            # Настройки нейросети
│
├── data/                        # Директория с данными
│   ├── train.csv
│   ├── test.csv
│   └── real_test_submission.csv # Разметка для теста (получена в notebooks/eda.ipynb)
│
├── src/
│   ├── data_prep/
│   │   ├── preprocessing.py     # Очистка, заполнение пропусков, OHE
│   │   └── dataset.py           # Stratified K-Fold PyTorch Dataset
│   ├── models/
│   │   ├── classic_models.py    # Scikit-Learn / Boostings + OOF train
│   │   └── tabular_nn.py        # Архитектура TabularMLP (Embeddings + Residual blocks)
│   ├── engine/
│   │   ├── classic_runner.py    # Пайплайн запуска классического ML
│   │   └── dnn_runner.py        # Тренировочный цикл PyTorch, валидация и EarlyStopping
│   └── utils.py                 # Фиксация сидов, сохранение чекпоинтов и лидерборда
│
├── checkpoints/                 # Сохраненные веса (.joblib и .pt, в .gitignore)
├── submissions/                 # Готовые сабмиты и leaderboard.csv (в .gitignore)
│
├── main.py                      # Обучение и оценка всех моделей
├── inference.py                 # Инференс по чекпоинтам и блендинг
```
### Замечания

Для улучшения архитектуры стоит добавить переход из train mode в validation mode для поиска гиперпараметров. А также придумать генерацию фичей

## Инструкция по установке и запуску

Склонируйте репозиторий в свое рабочее пространство. Настройте окружение (файл requirements.txt). Обучите все модели и получите лидерборд (python main.py). Если модели уже обучены и веса сохранены, запуск ансамбля запускается без повторного обучения (python inference.py). Итоговые результаты будут сохранены в папку submissions/
